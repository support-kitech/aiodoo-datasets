# Developer Guide

Welcome to the AIODOO Sources Framework! This guide is intended for maintainers aiming to extend, debug, or optimize the framework.

## Framework Overview

The AIODOO Sources Framework establishes a unified, deterministic environment representation. It completely isolates dataset generation (which focuses on AI, NLP, and AST manipulation) from infrastructure concerns (filesystem traversal, YAML parsing, hashing, caching).

## Folder Structure

```text
sources/
├── builders/          # Converts dicts/primitives to Domain Objects (e.g., ManifestBuilder)
├── cache/             # SQLite state persistence and CacheInvalidator
├── cli/               # Production arguments and commands via `python3 build_dataset.py`
├── constants/         # framework.py, cache.py, serialization.py
├── core/              # Private API: scanner, loader, interpreter, manager
├── domain/            # Public API: Frozen dataclasses representing immutable reality
├── exceptions/        # SourcesError and derived classes
├── factories/         # Domain assembly logic
├── index/             # Memory registry preventing duplicates
├── pipeline/          # The sequential orchestrator (SourcesPipeline)
└── tests/             # Pytest suite
```

## How RepositoryContext Flows

1. **CLI/Generator** requests load via `RepositoryManager.load()`.
2. `SourcesPipeline` instantiates `RepositoryLoader`.
3. `RepositoryLoader` parses `sources.yaml` into domain `RepositoryConfiguration`.
4. `SourcesPipeline` queries `CacheStore` using a deterministically computed hash of `RepositoryConfiguration` + `Directory State`.
5. If Cache Hit: `RepositoryDeserializer` hydrates `RepositoryContext` directly from SQLite.
6. If Cache Miss: `RepositoryScanner` traverses the filesystem, sending targets to `RepositoryInterpreter`.
7. `RepositoryInterpreter` produces `InterpretedModule` representations.
8. `ModuleFactory` uses `ManifestBuilder` and `RepositoryBuilder` to generate frozen `OdooModule`s and `Repository` instances.
9. `SourcesPipeline` flushes these to `CacheStore` via `RepositorySerializer`.
10. `SourcesPipeline` returns a `PipelineResult(success=True, context=RepositoryContext)`.

## Cache Mechanics

Caching works transparently. The SQLite database is usually created at `.aiodoo_cache/sources.sqlite` (or `datasets/sources.sqlite` via CLI).
- A **CacheKey** is generated by hashing the absolute paths, modification times of `sources.yaml`, and the `SOURCES_FRAMEWORK_VERSION`.
- The `CacheInvalidator` validates this key on every execution.
- Any change to Odoo file sizes, `sources.yaml`, or framework version forces a rebuild.

## Debugging

### Debugging Scanner Issues
If the pipeline fails to detect a module:
1. Verify the repository path in `sources.yaml` is absolute or correctly relative to execution context.
2. Ensure an `__manifest__.py` exists. The scanner drops directories missing manifests.
3. Run `aiodoo-sources scan --json` (or `python3 build_dataset.py`) to force a rescan and view verbose warnings.

### Debugging Cache Issues
If changes to source files are not propagating to generators:
1. Run `aiodoo-sources cache-info` to check validation state.
2. Ensure you haven't manually modified SQLite blobs.
3. Use `aiodoo-sources refresh-cache` to force invalidation.

## Extending the Framework

### Supporting New Odoo Versions
1. Add the version string to `sources/domain/repository.py` inside the `OdooVersion` Enum.
2. Update `ConfigValidator` if configuration schemas for newer versions require different structures.

### Extending RepositoryType
1. Add the type to `RepositoryType` Enum.
2. Modify `RepositoryLoader` if specific parsing rules apply to that new type.
